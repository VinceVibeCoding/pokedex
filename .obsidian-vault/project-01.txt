# Project 01 — Pokémon Card Price Intelligence Engine
Build plan derived from CLAUDE.md. Check off each step as completed.
North star: sub-second lookup of card ID + grade → pricing, stability, grade comparison, buy score.

## Phase 0 — Project Scaffold
- [x] Initialize Next.js (App Router) + TypeScript (strict, no `any`) + Tailwind CSS — Next.js 16.3.5 in `app/`, Node v24 via nvm
- [x] Set up PostgreSQL + Prisma (`npx prisma migrate dev` workflow) — Prisma 7.10.0, docker-compose.yml with Postgres 16 + Redis 7, containers running
- [x] Set up caching layer (Redis container running; app integration keyed by card ID pending) — `src/serving/cache.ts`, 5min TTL, degrades to DB if Redis is down
- [x] Create shared domain types module: `Card`, `GradeTier` (`raw`, `psa8`, `psa9`, `psa10`), `Comp`, `MarketSignals`, `BuyScore`, `GradePremiumAnalysis` — `app/src/types/domain.ts`
- [x] Verify commands work: `npm install`, `npm run dev`, `npm run build`, `npm test` — build ✓, typecheck ✓, prisma validate ✓ (note: `npm test` not wired yet — no test runner installed)

## Phase 1 — Data Model (schema for append-only comps + rollups)
- [x] Prisma model: `Card` (card ID, set, release date, type/rarity, pull rate, artist, print variant)
- [x] Prisma model: `Comp` (card ref, price, date, condition, grade tier, marketplace, source: TCGplayer | Collectr | 130point) — append-only, grade is part of identity; dedupe via `@@unique([source, sourceUrl])`
- [x] Prisma models: pre-aggregated rollup tables per card + grade tier (daily / weekly / monthly) — `CompRollup`
- [x] Migration + seed script with realistic fixture comps — migration `init` applied; `npm run db:seed` (idempotent) seeds 4 cards / 87 comps covering all edge cases: healthy liquid card, single-sale card, stale market (200d), zero-comps card, PSA 10 outlier

## Phase 2 — Analysis Module (pure functions, `analysis/`, unit-tested)
- [x] Market signals: sales count, most recent sale, velocity per day/week/month, price trend, volatility — per grade tier — `src/analysis/signals.ts`
- [x] Market Stability Index: composite of volume + recency + volatility (formula documented in code) — `src/analysis/stability.ts` (weights 40/30/30)
- [x] Buy Score: transparent heuristics first (trend slope, velocity, deviation from moving average) — explainable in UI — `src/analysis/buyScore.ts` (starts at 50, reasons[] per adjustment)
- [x] Grade Premium Analysis: price-to-value across raw / PSA 8 / 9 / 10 (incl. grading cost) → recommended tier — `src/analysis/gradePremium.ts`
- [x] Suggested price at different markup levels — `src/analysis/pricing.ts` (30d median base, markups 0/5/10/15/20%)
- [x] Unit tests with edge cases: 0 sales, 1 sale, huge outlier sale, stale last sale, sparse grade tiers — Vitest, 19/19 passing

## Phase 4 — Serving Plane (fast, sync — reads precomputed snapshots only)
- [x] API endpoint: card ID + grade → full snapshot (all grade tiers in ONE self-contained response) — `GET /api/cards/[cardId]?grade=`
- [x] No live external API calls in the request path — reads Card + 90d comps from Postgres only
- [x] Response caching by card ID, TTL keyed to ingestion freshness — Redis, 5min TTL, verified via KEYS
- [x] "Insufficient data" as a valid response state per grade tier (not an error) — verified: psa8 null on sv01-198 while other tiers populate
- [x] Verified live: 404 unknown card, 400 invalid grade, 200 valid grade; ~10ms warm lookups
